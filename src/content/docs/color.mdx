## Overview 

The color space used by SOL is [okLCH](https://developer.mozilla.org/en-US/docs/Web/CSS/color_value/oklch). Why okLCH? Color contrast becomes easier to predict compared to other color spaces like RGB or HSL. 

## Color Schemes

SOL supports light and dark schemes by default. 

LightningCSS requires `color-scheme` to be well-defined in order to transform `light-dark()` values for unsupported browsers. 

```css
:where(html) {
  color-scheme: light dark;
}
```

To avoid any flash of unstyling, add the following `<meta>` to your `<head>`: 

```html
<meta name="color-scheme" content="light dark" />
```

However, sometimes a project may only require a single scheme. 

By example, overwrite the color scheme value without a dark mode.

```css
html {
  color-scheme: unset; /* `unset`, `initial` or `light` */
}
```


## Color Palettes

SOL uses palettes, ~~brazenly borrowed~~ shamelessly stolen from [Open Props](https://open-props.style/). Thereby, theming should be simpler? At least, less CSS.

More info:  
[Open Props v2 Color Guide](https://opv2-beta.netlify.app/color/)  
[Open Props oklch Palettes Beta](https://nerdy.dev/open-props-oklch-palettes-beta)

SOL provides 4 color palettes: 

```css
--color-primary-{1-16}  
/* (Brand color scale) */ 

--color-secondary-{1-16}  
/* (Secondary color scale, optional) */ 
  
--color-gray-{1-16}  
/* (Neutral color scale) */

--color-utility-{1-16}  
/* (Utility colors such as success, warning, error) */  
```

### Primary Color Palette

[View primary color swatches](#color-palette-primary)  

Override the default primary hue with any pre-defined `--hue-*` values, or use a number: 

```css
--primary-hue: var(--hue-*)
/* 
--hue-{red | pink | purple | violet | indigo | blue | cyan | teal | green | lime | yellow | orange} 
*/
```

[See all hue options](#hue-options)

#### Primary Palette Configuration

```css
:root {
  --primary-hue: var(--hue-indigo);
  --primary-hue-rotation: 0;
  --primary-chroma: 1;
}
```

### Secondary Color Palette

[View secondary color swatches](#color-palette-secondary)

Similar to setting the primary hue, to override the default secondary hue, use any pre-defined `--hue-*` value, or use a number: 

```css
--secondary-hue: var(--hue-*) 
/* 
--hue-{red | pink | purple | violet | indigo | blue | cyan | teal | green | lime | yellow | orange} 
*/
```

[See all hue options](#hue-options)

#### Secondary Palette Configuration

```css
:root {
  --secondary-hue: var(--hue-pink);
  --secondary-hue-rotation: 0;
  --secondary-chroma: 1;
}
```

### Gray Color Palette

[View gray color swatches](#color-palette-gray)

By default, the gray palette tone is influenced by the `--primary-hue` by `0.1` of chroma which gives the neutral scheme a subtle hint of primary color. However, any of these settings can be changed.

#### Gray Palette Configuration 

```css
:root {
  --gray-hue: var(--primary-hue);
  --gray-hue-rotation: 0;
  --gray-chroma: 0.1;
}
```

### Utility Colors 

Utility colors serve a specific purpose; not meant for branding. For example, a red color might be used to indicate an alert. 

To use a specific utility color, define the `--utility-hue` first. Then specify a number from the `--color-utility-*` scale.

#### CSS Example 

```css
mark {
  --utility-hue: var(--hue-yellow);
  background: var(--color-utility-4);
}
```
